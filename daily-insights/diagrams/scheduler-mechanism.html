Social Media Daily & Monthly Insights: sync mechanism

Every sync, scheduled or from a button, is an Integration Sync Request row. The dispatcher runs it through one <Platform> - Run Sync flow, which runs the steps one after the other. The 4 platforms run in parallel; one platform never runs two syncs at once. All times are Riyadh time.

Social Media - Scheduled Sync Recurrence: every day 05:00, 08:00, 12:00, 16:00 One request per platform with Set Up = Yes and Connection Active not No.
05:00 → Scheduled Daily (with data; Weekly Run on Fridays)
08 / 12 / 16 → Scheduled Intraday
Triggered By = Schedule (no notification)

Inside <Platform> - Run Sync (in order)
1. Data05:00 run, and All Time with Data and InsightsGet <Platform> Campaigns, then the cascade (Dataverse triggers on the parent ID column): ad sets / ad squads / ad groups / asset groups → ads.
Waits until no child data flow is running (checked every 2 min, two quiet checks in a row, at most 30 min).
2. Lifetimeevery runGet <Platform> Insights: lifetime metrics on the synced tables.
3. Dailyevery runGet <Platform> Daily Insights (start date, end date, closed through): one row per item and day with delivery.
4. Monthlyevery runGet <Platform> Monthly Insights (first month, last month): one row per item and month from the source; months without data get an empty row (No Data = Yes).
5. Resultevery runSteps Log and status on the Integration Sync Request (Succeeded / Failed / Skipped). A failed step is logged and the next step still runs.

Period Closed rules (scheduler and buttons)
Day: closed when it is the day before yesterday (D-2) or older.
Month: closed when older than the previous month; the previous month closes on the current month's last Friday.
Today and the current month are never closed.

D-2 = the day before yesterday. Platforms can still revise older numbers (Meta up to 28 days, Google Ads conversions up to 90 days); the Friday reloads pick them up. Days without delivery get no daily row.
